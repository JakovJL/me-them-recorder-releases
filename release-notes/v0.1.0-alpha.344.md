# Me/Them Recorder 0.1.0-alpha.344

Changes since **0.1.0-alpha.292**.

Windows testing prerelease for explicit evaluation. It adds the opt-in Interview Ghost, renames the application executable, and includes the user-facing work below.

## Interview Ghost (opt-in, Call recordings, Nemotron streaming only)

- Ghost is a separate interview mode over Call capture. It appears only with the Nemotron streaming engine; on other engines the scenario row is hidden and Start is never blocked.
- Quick and Full answers have independent slots and can be requested separately. Each uses its own primary/reserve provider route; a failed primary may fall back before content, and a partially streamed answer is never mixed with another provider.
- Each press uses one frozen snapshot of the conversation, saved profile, and prior suggestions. Prior suggestions are treated as not spoken, so they are not mistaken for interviewer speech.
- The latest interviewer question is pinned explicitly after the history, including a question that is still gray/uncommitted. The request explicitly targets this question while retaining earlier speech as context.
- Answer text and details are selectable and copyable in the current card, prior answers, and history cards.
- The overlay is a compact single window. Background transparency is user-controlled while answer text and controls stay opaque; the answer area fits its content.
- Native capture exclusion, hide, and click-through are reversible. Exit restores the previous tray, taskbar, title, and window geometry.
- Alt+9 opens a short shortcut list showing the actual bindings. If a shortcut cannot register, the overlay shows the Windows reason/code; retry re-registers only the failed binding and keeps working ones.

## Executable name and packaging

- The application now launches as `MeThem.exe`. `MeThemRecorder.exe` remains as a compatibility launcher for existing shortcuts, pinned items, and scripts; it forwards arguments, working directory, and environment to `MeThem.exe` and exits without starting a second GUI.
- Installer AppId, writable profile/data location, and updater asset names are unchanged, so existing installations keep their update path and profile.
- Local Runtime assets and protocol are unchanged; existing Local Runtime installs remain compatible.

## Other changes since 0.1.0-alpha.292

- Accessibility and UI pass: reduced-motion coverage, a shared loading spinner, larger hit targets, locale-native digits for sizes/costs/tokens/search, clearer field names, protected deletions, long-content wrapping, tab-strip behavior, history-row actions, workspace-tab and calendar keyboard support, and clearer history-row actions.
- Model cards and the Settings dialog were reworked; the dialog no longer has a separate title bar. Link buttons no longer use dotted underlines.
- The Participation tab gains an interactive timeline, moment records, and per-speaker word counts.
- A session **Logs** window is available with Copy and Save, backed by an in-memory session buffer.
- Workspace and history: meeting titles persist across saves; the open meeting refreshes after a History rename; export and copy follow the current workspace; completed audio playback restarts from zero; citation clocks reveal the nearest transcript line; the Space recording shortcut now works only in the Recorder.
- Reliability: workspace state stays coherent across delete, cancel, and startup; batch-import progress stays visible while conflicting actions are locked; sidebar configuration is locked during capture and pause; draft retry keeps its audio and draft state safe from cleanup and rename.
- Glossary: editor races and silent drops are fixed; Undo is persisted before success; speaker names stay coherent through glossary Undo; meeting results are retained.
- Data and integrations: the read-only MCP surface exposes saved Q&A and Interview results with provenance, role, and speaker identity; meeting metadata records the recording mode, a stable saved date, and version stamps while existing meetings still load; pyannote batch sizes are capped on low-VRAM GPUs.
- Fixed a startup crash in the packaged transparent window. The release smoke now also checks the Qt backend and window adapter.
- The native Live Runtime is refreshed (livefix4) with SIMD paths and an LLVM-built Vulkan artifact.

## Validation and limits

- Canonical release checks passed: 1,725 Python tests, 948 frontend tests, the production frontend build, frozen application smoke, installer install/uninstall, and upgrade compatibility with the previous executable name.
- The final installed Qt application starts normally on Windows 10 22H2. Both Quick and Full Copy buttons were checked against the Windows clipboard using synthetic answers; Ghost entry/exit and shortcut registration also passed.
- An isolated real WebView2 check on Windows 10 22H2, earlier in this Ghost series, passed for capture exclusion, background alpha, and reversible input/window state. It did not cover a live conferencing call.
- Real call/provider and conferencing acceptance, Windows 11 coverage, and physical hotkey coverage remain pending. Quick and Full latency are best effort; no fixed latency figure is promised.
- Capture exclusion and background transparency depend on the Windows version, graphics backend, and the capturing application. Verify them with your conferencing or capture software. No guarantee of invisibility, zero latency, or universal compatibility is made.

**Known issue:** after stopping a recording and exiting Ghost, a long Interview history may remain visible on the Recorder. Saved answers remain available in the meeting and in Markdown export.

## Tester checklist

- Ask two interviewer questions. While the second is still gray/uncommitted, press Get answer and confirm it targets that question, not the first; check that Quick and Full land in their own slots.
- Copy an answer from the current card and from a prior/history card.
- Restart the app and confirm Ghost shortcuts still work; open Alt+9 help; if possible, trigger a shortcut conflict and check the reason/code plus retry behavior.
- Record a Call with microphone and system audio: verify me/them separation, live lag, pause/resume, and Stop.
- With conferencing or capture software, verify capture exclusion and the transparency levels you plan to use.
